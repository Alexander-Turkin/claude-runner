# crun

Автономный раннер задач для Claude Code. Вы описываете задачи в свободной форме,
запускаете одну команду и получаете их выполненными по очереди — без подтверждений,
с чистым контекстом на каждой задаче и с git-коммитом после каждой проверенной.

```
crun
```

Дальше — четыре экрана: выбор проекта, выбор папки с задачами, предпросмотр, подтверждение.
После подтверждения вопросов больше не будет.

## Установка

```bash
bash ~/claude-runner/install.sh
```

Ставит `claude` CLI (если его нет), кладёт симлинк в `~/.local/bin/crun`, дописывает PATH.
Запускать **из обычного терминала**, не изнутри сессии Claude Code.

## Задачи

Одна задача — один `.md`-файл в любой папке проекта. Формат произвольный: раннер сам
переведёт текст в свой спек (цель, критерии приёмки, команда проверки, риск, открытые
вопросы) и положит результат в `.claude-runner/compiled/`. **Ваши файлы не изменяются.**

Порядок — по номеру в имени файла: `010-*.md`, либо схема этапов `T0.1`, `T0.2`, `T1.1`.

Если хочется задать всё явно, добавьте frontmatter — тогда компилятор не будет
обращаться к модели:

```markdown
---
title: Экран списка карт
verify: pytest tests/test_cards.py
---
Описание задачи…
```

Поле `verify` — команда, которой раннер **сам** проверит результат. Это источник истины:
если модель отчиталась об успехе, а команда упала, задача считается проваленной.

## Что раннеру разрешено

Режим `dontAsk`: разрешено ровно то, что в `config/allow.json`, всё остальное молча
отклоняется. Внутри — чтение и правка файлов проекта, локальные утилиты, git на чтение,
сборка и тесты.

**Запрещено:** сеть (`curl`, `git push`, `npm install`), секреты (`.env`, `~/.ssh`,
keychain, `env`/`printenv`), `sudo`, `rm`.

Секреты закрывает не список правил, а PreToolUse-хук `hooks/guard-secrets.sh`: он
разбирает фактическую команду и ловит обход в любой форме — `cat ./.env`,
`bash -c "..."`, `grep` по абсолютному пути. Каждое срабатывание пишется в
`.claude-runner/logs/guard.log`.

Упёршись в запрет, Клод не ищет обходных путей, а останавливается и пишет
`.claude-runner/NEEDS_INPUT.md`: что добавить, зачем и как. Код выхода — 2.

## Модели

Планирование и реализация разведены: **Opus компилирует** задачи (понять размытую
постановку — самое дорогое место для ошибки), **Sonnet выполняет** (быстрее и дешевле,
а спек к этому моменту уже однозначен).

Переопределяется флагами `--plan-model` / `--model` или в конфиге проекта.

## Прогресс

По ходу задачи видно, что делается и зачем:

```
[2/7] T0.2 · Конфигурация и логирование
  • Смотрю архитектуру, чтобы взять структуру пакетов
  ⋯ Read   02-architecture.md
  ✎ Write  bot/config.py
  $ python3 -c 'import bot.config'
  ⊘ Blocked by crun secret guard: …
✓ готово · 1:12 · $0.38 · 14 шагов
```

`⋯` чтение · `✎` запись · `$` команда · `⊘` отказ · `•` мысль модели · `~` рассуждение.
Если шаг долгий, раз в 20 секунд печатается `⋯ ещё работаю (1:05)`, чтобы было видно,
что процесс жив. `--quiet` убирает построчный вывод, полный транскрипт всё равно
пишется в `.claude-runner/logs/<id>.jsonl`.

## Прерывание

Ctrl+C останавливает прогон, снимает запущенный `claude` и прибирает временные файлы.
Уже скомпилированные задачи и выполненные шаги сохранены: следующий запуск продолжит
с того же места, а не начнёт заново.

## Настройка на проект

`.claude-runner.json` в корне проекта:

```json
{ "planModel": "opus", "model": "sonnet", "budget": 5, "timeout": 1800,
  "extraAllow": ["Bash(pip install*)"], "extraDeny": [] }
```

## Команды

```
crun                       выбрать, показать план, запустить
crun <проект> [папка]      без интерактивного выбора
crun compile               только скомпилировать и показать, как поняты задачи
crun status                что сделано, что осталось
crun new "название"        создать файл задачи из шаблона
```

Флаги: `--yes`, `--dry-run`, `--only <id>`, `--limit N`, `--model`, `--plan-model`,
`--quiet`, `--no-commit`, `--continue-on-error`, `--retry-failed`, `--recompile`,
`--allow-dirty`.

Коды выхода: `0` — всё сделано, `1` — задача провалена, `2` — нужен ваш ввод.

## Что появляется в проекте

```
.claude-runner/
├── compiled/    спеки задач (.json) и их читаемые версии (.md)
├── state.json   статус каждой задачи
├── PROGRESS.md  история выполненного — подмешивается в контекст следующих задач
├── NEEDS_INPUT.md
└── logs/        сырые ответы, вывод verify, guard.log, LAST_FAILURE.md
```

Статус хранится в `state.json`, поэтому исходные файлы задач никуда не двигаются.
Ключ задачи — SHA её содержимого: правка исходника автоматически требует перекомпиляции.

## Границы

Allow-лист и хук защищают от случайного вреда, но это не песочница ОС: у Клода есть
доступ на запись к файлам проекта. Настоящая страховка — git-коммит на каждую задачу:
любую можно откатить через `git revert`. Раннер требует чистое рабочее дерево перед
стартом, чтобы чужие изменения не попали в его коммиты.
